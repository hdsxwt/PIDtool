# PIDtool

STM32 PID 调参工作台：串口实时可视化 + 脚本化实验 + AI 闭环自动调参 + 授权式代码修改。

配合固件侧的 [串口协议](docs/PROTOCOL.md)（提供 [STM32 C 参考实现](docs/firmware/pid_protocol.h)），
把"改参 → 观察 → 评价 → 再改参"的循环从手动敲串口助手变成半自动/全自动流程。

## 功能一览

- **实时波形**：目标/反馈、误差、输出与 PID 分量三栏滚动显示，可冻结/清除
- **手动实验**：在线下发增益与目标值，一键采集并自动计算阶跃指标
  （上升/峰值/超调/调节时间/稳态误差/振荡检测）
- **脚本化实验**：阶跃响应、扰动抑制两套流程，含人工提示（倒计时横幅、
  "请施加/停止阻力"确认）与波形事件竖线标注
- **AI 闭环自动调参**：DeepSeek 根据历史轮次指标提议新参数，自动实验、
  评分、保留最优、振荡/退化早停，结束时恢复最优参数
- **参数导出**：生成 `config.json` 与可直接粘贴的 `pid_config.h`
- **授权式代码修改**：需要结构性修改时，由 opencode 在**限定范围**内改代码；
  强制 git diff 审查，保留或一键回滚
- **工作区隔离**：每个固件目录独立配置与历史（`.pidtool/`），互不干扰
- **无硬件可玩**：内置闭环电机模拟器（含抗饱和 PID），全流程可离线验证

## 安装

要求 Python 3.11+（Windows）。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

依赖：PySide6、pyqtgraph、pyserial、numpy、tomli-w、openai（AI 调参）。

## 快速开始（无需硬件）

```powershell
.\.venv\Scripts\python.exe main.py
```

1. 工具栏"工作目录 → 浏览"选择一个目录（或随便建一个空目录）
2. 链路保持"模拟器"，点"连接"
3. 在"实验"页修改目标值并"下发目标值"，观察波形与指标
4. 想体验自动调参：在"AI 调参"页填入 DeepSeek API Key → 保存 → 开始

## 连接真实板子

1. 固件按 [协议规范](docs/PROTOCOL.md) 实现（可直接用 C 参考实现），或为已
   有协议写[适配器](docs/ADAPTER.md)
2. 工作目录选择固件工程目录；链路选"串口"，选好 COM 口与波特率，连接
3. 点"开始遥测"应看到波形；无数据请查[协议文档的调试建议](docs/PROTOCOL.md#10-调试建议)

## 界面导览

底部四个页签：

| 页签 | 用途 |
| --- | --- |
| 实验 | PID 参数在线下发、手动采集/指标、自动化实验（阶跃/扰动） |
| AI 调参 | 自动调参控制、迭代日志、DeepSeek 设置 |
| 代码修改 | 需求描述 → 预览 → 授权执行 → git diff 审查 → 保留/回滚 |
| 历史 | 全部试验记录（含参数与指标），可导出选中轮次参数 |

### 自动化实验

- **阶跃实验**：等待稳定 → 采集基准 → 倒计时后下发阶跃 → 出指标
- **扰动实验**：倒计时提示"开始用手给电机施加阻力，坚持 N 秒" → 标记扰动开始 →
  到时提示"请停止并确认" → 恢复期采集 → 出扰动指标（最大偏差/恢复时间）

### AI 调参流程与安全

任务层级：一份完整方案 = 测试循环×N × 轮次列表；每一轮 = 若干动作（如 0→300→600→扰动）
依次执行；一轮的全部动作结果统一发给 AI 评估一次（轮评分 = 各动作评分均值 + 方差，
惩罚动作间不一致），随后应用 AI 给出的下一组参数。在"调参方案…"弹窗中可增删/排序
轮次与动作，并单独配置每个动作的参数（目标/基线/稳定时间/倒计时/观测时长/扰动与恢复
时长）。扰动动作需要你按横幅提示施加/停止阻力；等待 AI 返回与调参结束时电机会自动停机。

安全机制：工作区限幅、自动记录每轮、**结束时恢复历史最优参数**、连续振荡
或连续退化自动早停、随时可中止。API Key 只保存在本机全局配置
（`%APPDATA%/PIDtool/app.toml`）。

可选数据：勾选"发送降采样原始波形给 AI"后，每轮响应会附上约 80 点降采样波形
（t/sp/fb/u/up/ui/ud），帮助 AI 判断超调形态与输出饱和；默认关闭（开启会增大
token 消耗）。

### 代码修改（opencode）

前置条件：工作目录是 git 仓库、已跟踪文件无未提交改动（保证可以安全回滚）。

流程：写需求 → "生成预览"（显示将执行的命令与完整提示词，并做预检查）→
"授权执行" → 实时输出日志 → git diff 审查 → **保留修改**（记入历史）或
**回滚修改**（还原全部改动并删除本次新建文件）。

说明：

- 默认命令为 `opencode run --dir <工程> "<提示词>"`（默认**不传** `--auto`）；
  可在页内改可执行文件路径/受限 agent/超时
- 每次"授权执行"前会弹出确认框，列出将执行的命令与风险边界；若需要让代理
  自动编辑，请在页内显式勾选"自动批准工具权限（--auto）"（高风险，勾选时会
  再次警告确认；默认关闭，未启用时代理可能因权限受限无法编辑）
- 提示词内置范围约束（仅 PID 相关源文件、不烧录）
- **边界提醒**：diff 审查与回滚只覆盖仓库内 git 可见的改动；仓库外副作用
  （写文件、联网、改系统状态）不可见也不可回滚，工程内容还可能影响代理行为
  （prompt injection）——请只对信任的工程与仓库来源使用该功能
- 编译与烧录由你手动完成或另行授权，工具不会自动烧录

## 导出与固化

调参满意后，在"历史"页选中对应记录 → "导出选中为 config.json / .h"：

- `.pidtool/exports/config.json`：参数 + 来源 + 指标（最新）
- `.pidtool/exports/config_<时间戳>.json`：历史副本
- `.pidtool/exports/pid_config.h`：`#define PID_KP ...`，粘贴进固件即可

数据格式详见 [docs/DATA_FORMATS.md](docs/DATA_FORMATS.md)。

## 打包为 Windows 可执行程序

```powershell
.\build_win.ps1
```

产物在 `dist\PIDtool\`（约 170 MB，免安装）：

- 把整个 `dist\PIDtool\` 目录复制到程序目录，例如
  `C:\Program Files\PIDtool`（需管理员）或 `%LOCALAPPDATA%\Programs\PIDtool`（无需管理员）
- 右键 `PIDtool.exe` → 发送到 → 桌面快捷方式
- 运行时配置仍写在 `%APPDATA%\PIDtool\app.toml`，工作区数据跟随固件目录，
  与安装位置无关；需要版本升级时替换该目录即可

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 串口无数据 | 确认已点"开始遥测"、波特率一致、TX/RX 交叉、共地 |
| 状态栏 CRC 错增长 | 波特率不匹配或线路噪声，见[协议文档](docs/PROTOCOL.md) |
| AI 调参报"缺少 API Key" | 在"AI 调参"页填写并保存 |
| 代码修改报"不是 git 仓库" | 对该目录 `git init` 并提交一次；或换目录 |
| 代码修改窗口直接进入 TUI | 可执行文件指向了不转发参数的 .bat；改用 `opencode.cmd`/`opencode.exe` 全路径（工具会主动报错提示） |
| COM 口占用 | 关闭其他串口工具后点"刷新"重试 |
